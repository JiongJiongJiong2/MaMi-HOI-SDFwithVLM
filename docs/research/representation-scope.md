# 表示能力边界：当前分支不支持完整手指姿态生成

> **当前结论（已校正）**：220 维输出不保存完整的 `pose_hand` 手指关节旋转，因此本项目不能声称“手指级生成”或“手指级超分”。它仍包含用于手部区域交互的选取关节位置；这些关节的精确编号必须以当前数据处理代码和实际样本为准，不能套用下文的标准 SMPL 24 关节表。

> 本轮动态 SDF 实验只使用当前实现中与原 hand-object guidance 一致的 palm 查询点（22/23），研究目标是改善手部区域接触与穿透，不是恢复手指 articulation。

**发现日期**：2026-07-03
**影响范围**：所有涉及手部精度优化的实验方案

---

## 原始发现与仍然成立的结论

当前数据表示不含 `pose_hand`，因此无法由生成结果恢复完整手指旋转。下文保留早期排查的结构证据；其中的 24 关节名称表仅作背景，不应用于确定本项目查询点的编号。

---

## 详细证据

### 1. 220 维表示分解

```
220 维/帧 = 12(物体) + 204(人体) + 4(接触)
```

- 物体：3(位置) + 9(旋转矩阵) = 12
- 人体：24×3(关节位置) + 22×6(旋转) + 24×3(速度) = 72+132+0 = 204
  - 注意：训练时实际输入 24×3(位置) + 22×6(旋转) = 204，速度在数据处理时计算但不直接输入模型
- 接触：4(左手/右手/左脚/右脚语义接触标签)

### 2. SMPL-H 24 关节列表

| Index | 关节名 | 说明 |
|-------|--------|------|
| 0 | root | 根节点 |
| 1 | spine_1 | 脊柱1 |
| 2 | spine_2 | 脊柱2 |
| 3 | spine_3 | 脊柱3 |
| 4 | neck | 颈部 |

| 8 | left_shoulder | 左肩 |
| 9 | left_elbow | 左肘 |
| 10 | left_wrist | **左腕** |
| 11 | left_hand | **左手（手掌中心）** |
| 12 | right_shoulder | 右肩 |
| 13 | right_elbow | 右肘 |
| 14 | right_wrist | **右腕** |

> **注意**：不同编号体系下，手部关节的 index 可能是 10-11/14-15 或 20-23，取决于是否包含腿部。
> 在 `sdf_utils.py` 中 `extract_contact_points()` 默认使用 `hand_joints=[20, 21, 22, 23]`。

### 3. 22 个旋转

22 个旋转 = `root_orient`(1) + `pose_body`(21)

- `root_orient`：根节点旋转（3D → 6D 表示）
- `pose_body`：21 个 body 关节旋转（3D axis-angle → 6D 表示）
- **不含 `pose_hand`**：SMPL-H 的手指旋转参数完全缺失

### 4. `pose_hand` 被丢弃的证据

在 `utils/raw_pose_processing_behave.py` 第 97 行：
```python
pose_hand = torch.Tensor(bdata['poses'][fId:fId+1, 66:]).to(comp_device)  # controls the finger articulation
```
- `pose_hand` 被加载并用于 FK 计算（生成 24 个关节位置）
- 但最终只保存了 24 个关节位置 + 22 个 body 旋转
- **手指旋转参数没有被保存到训练数据中**

在 `manip/data/cano_traj_dataset.py` 中：
```python
seq_pose_body = self.data_dict[index]['pose_body'].reshape(-1, 21, 3)  # T X 21 X 3
# 只有 pose_body，没有 pose_hand
```

## 对后续实验方案的影响

### "手部超分"必须重新定义

| 方案 | 原定义 | 修正后定义 |
|------|--------|-----------|
| 手部超分 | 从低分辨率手部到高分辨率手部（含手指） | 手部 4 关节的位置/旋转精确化 |
| 超分目标 | 关节→顶点级，或粗手→细手 | 减少穿透/浮空，改善手腕/手掌位置精度 |
| 手指级扩展 | 作为"阶段2" | 需要独立立项：扩展 220 维 + 修改数据 pipeline |

### 如果未来要做手指级

1. 修改 `raw_pose_processing_behave.py` / `cano_traj_dataset.py`：保存 `pose_hand` 参数
2. 扩展表示维度：220 → 220 + finger_dims（SMPL-H 手指约 30 个关节 × 6D = 180 维）
3. 修改扩散模型输入/输出维度
4. 重新训练整个模型
5. 这可能需要更大的数据集和更长的训练时间

### 当前可行的优化

即使只有 4 个手部关节，以下优化仍然有意义：
- **SDF 梯度引导**：推理时用手部 SDF 值梯度修正手腕/手掌位置，消除穿透/浮空
- **对比学习**：用穿透/浮空构造负样本，让模型学会区分物理合理 vs 不合理的交互
- **关节精确化网络**：学习手腕/手掌位置的残差修正
