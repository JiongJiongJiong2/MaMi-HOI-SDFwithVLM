# 跨会话研究实施约定

当前入口：[研究状态](../../RESEARCH_START_HERE.md)。这份约定针对本项目多会话落地，不规定模型品牌，也不要求每个实现细节都再次请示。

## 会话职责与授权

研究讨论决定问题、协议变更和对证据的解释；实施会话完成一个实验编号下的一段可验证工作。当前 CTP-01 的 T0 资产检查、T1 有界执行 smoke、T2 无学习对照按各自提示词顺序领取，满足前置条件后无需为普通实现选择重复询问。新模型正式训练、扩展数据获取、扩大 GPU 预算不隐含在文档整理或 smoke 中。

启动先核对 cwd、Git root、branch、HEAD、dirty files，读取入口、协议和交接。用一小段话说明本次问题、终点、当前缺口，然后实施。未提交变化按所有者保留，不能顺手提交、清理或回滚。

## 必要修复如何回到实验

路径、依赖、等价分块、日志和形状错误可自主修复。修复坐标、标签处理或评估实现时，记录旧产物失效范围并重跑受影响对照。三次连续尝试仍无进展时，先整理复现、已排除原因和最小替代方案；有证据支持的范围内继续，缺少真实前提则留下可复现阻塞记录。

更换标签定义、split、主要指标、基线、动作预算、核心机制属于协议变化。修正客观错误也要保留前后版本；不能覆盖旧结果使其看起来一直正确。不得通过删难例、改阈值、反复查看 test 把 NO-GO 调成 PASS。统计证据不足、执行失败和机制负结果分别记录。

修复日志必须说明“阻塞哪个研究步骤、影响哪项证据、修好后回到哪个命令”。非阻塞重构、新架构和额外功能只进入待办，不自动实施。

## 状态与证据

状态使用：待执行、实现完成、smoke 已验证、正式运行完成、结果已复核、证据不足、版本 NO-GO、阻塞、待研究决策。避免只有一个 PASS。代码完成不是训练完成，单元测试不是研究结论，报告写完不是原始结果已复核。

每项结果附代码 commit/未提交 diff 标识、实际配置与输入版本、划分、随机种子、命令、输出路径和统计单位。重要输入可存哈希，不将数据/checkpoint 批量入 Git。不把窗口、候选、seed 当成独立参与者或独立序列。

## 本地与服务器

本轮文件整理没有连接服务器。实施时若需要现有服务器，先只读检查是否已有相关任务、输入和环境，避免重复启动。使用既有授权的环境；没有连接信息时明确记录缺口，不编造服务器状态。不开新付费实例，不关机、不删除数据，不终止其他任务。

每个实验使用独立输出目录并存 resume 信息。记录本地与远端代码版本；不能把“本地已提交”写成“远端已同步”。发现旧进程在运行时确认产物所属实验，而不是启动同名第二份。

## 上下文与 Git

入口保持简短；历史报告按需加载。恢复上下文或换模型时，读当前协议和交接，不把聊天总结当真值。更新进度应发生在检查点和中断前，而不仅在最后一句回复里。

同一工作区同时只由一个实施任务修改相同代码。并行需要独立 worktree 与产物目录；同时不共享可变配置。每个有意义的已验证结果按 AGENTS 要求做聚焦提交，明确哪些内容未验证。用户拥有的其他未提交文件原样保留。

## 交接输出

沿用 [交接文件](implementation-handoff.md) 的字段。结束时说明本次实际回答了什么、尚不能说明什么、下一项具体动作。有效负结果可以完成本次任务；不得自动转向未领取的新实验。
